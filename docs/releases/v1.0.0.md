# ZROtext 1.0.0 candidate

This document describes the source and Android version prepared for 1.0.0.
Android uses version name `1.0.0` and version code `14`, following
`0.1.7-rc.3` / code `13`. Publication and downloadable artifact identities belong
to the reviewed GitHub Release and its receipts; this document does not identify
an already published release.

## Included changes

- A compact dark-green owner workspace with separate navigation destinations,
  contextual phone details and a focused Add phone flow.
- Guided Android setup with visible navigation, full-value comparison and an
  authenticated existing-key binding handoff. The normal flow no longer asks
  users to copy device identifiers or stream addresses. SIM choice, permissions,
  connection start and line approval remain explicit decisions.
- Hosted account registration, original-browser email verification and password
  fallback. Interrupted setup resumes from current server facts. Verification
  does not silently sign in or replace an existing session.
- An isolated hosted billing implementation with disabled, TEST and LIVE modes,
  current provider/catalog verification and durable checkout reconciliation.
  Recovering an uncertain checkout retains its original operation; it does not
  automatically create another purchase. Availability depends on verified
  runtime capabilities and operator configuration.
- Account lifecycle anchors, immutable child ownership, membership-change
  fencing and isolated reviewer components. The new profile03 record readers
  are unmounted prerequisites; they do not enable profile03 sending.
- The accumulated SDK/native contract and package-verification work from the
  review-queue consolidation, plus refreshed Go candidate networking dependencies.
- Explicit comparison-length guards from #1524. The locked comparison library
  already rejects unequal slice lengths; these guards clarify existing behavior.

The setup behavior and recovery requirements are maintained in the
[workspace design](../design/owner-workspace.md),
[setup observations](../setup-observations.md) and
[hosted billing runtime](../hosted-billing-runtime.md) documentation. The source
integration is recorded in #1370 and #1523; the comparison cleanup is carried by
#1525.

## Upgrade and compatibility

The source includes numbered database migrations through `107`. Preserve all
existing migration bytes and use the maintained migrator and runtime-role
provisioner. Back up the database and qualify a restore before upgrading an
operated installation; an older binary is not a database downgrade procedure.
Hosted runtime markers and namespace restrictions must be respected by every
process using a scoped database.

Retain the enrolled Android key and independently retained owner recovery
material. A restart can recover an existing binding; reinstalling or losing its
key requires explicit recovery or pairing rather than inventing a replacement
identity. Review current account, session, SIM and line state after upgrading.

The app version does not replace independently versioned SDK/package contracts.
Existing protocol and runtime gates remain in force. Self-hosted operation and
TEST billing do not acquire LIVE entitlement through this version change.

## Qualification and limits

Candidate CI and unsigned-build receipts must refer to the exact source commit.
Use the [release procedure](../RELEASING.md) and
[release bundle verification](../RELEASE-BUNDLE.md) for source tags, server image,
Android checksum, SBOM and signing-certificate verification. An unsigned APK is
for inspection and cannot establish signed distribution acceptance.

The 1.0.0 version does not establish a generally available hosted service,
Google Play acceptance, physical handset/key-lifecycle qualification, carrier
delivery or production readiness. General sending, maintained receiver/profile03
integration and controlled-device pilot gates remain tracked separately. Live
payments, deployment, signing and distribution require their own completed
acceptance and maintainer decisions. See the [roadmap](../ROADMAP.md) and
[hosted readiness](../HOSTED-READINESS.md) for those boundaries.
