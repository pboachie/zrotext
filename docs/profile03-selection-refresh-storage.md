# Same-phone physical selection storage

Migration111 retains a separately approved physical selection after the same
enrolled phone reconnects. It pins the actual accepted03 election, immutable
binding, root, manifest, hardware reader and original signed subscription ID.
Subscription equality does not prove physical SIM identity. The original v2
activation, installation, signatures, election and binding generation remain
unchanged. Unknown later manifest ancestry refuses this bounded path.

The runtime receives SELECT and four narrow functions: reserve, device proof,
owner approval and installed ACK. SQL reconstructs the exact496 core's actual
scope and validates the complete121-byte observation's structural ranges. It
does not authenticate a caller, verify signatures, consume MFA or recreate an
opaque local phone handle. The application independently verifies all original
evidence and fresh signatures. Reserve and approval require separate genuine
owner password/MFA proofs; the first device installation ACK checks the current
device scope after historical approval, without fabricating a current owner
session after sign-out.

Original745-byte bundles and first accepted/installed times are retained.
First installation must commit before the original core expires. Exact retries
return their original rows without renewal or anchor tuple updates. At most16
reservations are retained per binding and full device connection, and at most
one approval can be accepted for that connection. A genuinely new connection
has a distinct scope while keeping every previous attempt.

A fresh explicit reservation can irreversibly close expired never-approved
predecessors. Each deferred link names the later reservation under the exact
same physical scope; closure time equals its issued time. Complete ancestor
chains survive interrupted responses. A retained device proof permanently
fences original-v2 fallback for that connection, including after expiry or
closure. Current readers must check that retained history and require an exact
installed refresh. Status and historical retries never close, allocate or renew.

Every new state mutation versions the actual retained account-anchor tuple
under the mandatory account fence while preserving epoch1 and identity. Old
repeatable-read and serializable snapshots must fail when they lock that row.
Deferred completion repeats current structural scope and actual primary
deadlines after transaction waits. Closed schema/body/declaration/ACL checks
evolve only to known111; absent, partial, disabled, unknown and polluted graphs
refuse. Runtime row, column, helper and epoch writes remain denied.

These receipts establish no message permission. Per-message admission and
grant/fetch must retain and compare the exact original physical receipt, owner
permission and full lease; reconnecting never translates an earlier reviewed
message. Typed03 conversation/admission/effect writers remain separate work,
and all legacy02 writer restrictions remain in force. SQL qualification is
separate from application authentication, cryptography, device acceptance and
release readiness.
