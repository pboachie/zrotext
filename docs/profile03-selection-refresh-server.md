# Explicit same-phone selection restoration

The optional server library restores selection for the same enrolled phone,
elected binding and original selected subscription after a new connection. It
does not replace the phone, regenerate pairing keys or rewrite original
activation, election or attempt history. Subscription equality does not prove
the same physical SIM; the phone must obtain a genuine fresh complete
observation and preserve its separate local hardware/issuer checks.

A genuine current original owner opens a durable reservation with password and
one-use MFA. The actual current enrolled socket signs the exact496-byte refresh
core and121-byte observation. After independently comparing that proof, the
original registered SEALED approval key signs the exact bundle, and a distinct
fresh password/MFA factor approves it. The factor used to reserve cannot also
approve. Root, reader, SMS and message-signing keys are not substitutes.

Actual latest signed material is resolved through independently verified accepted
ancestry. Opening restoration does not require the physical handle it is meant
to restore. Original ten-field evidence remains historical; downloaded evidence
and parsed JSON do not establish a current lease or selection. All mutations
revalidate actual original proof, binding, root, current reader, full device
lease, selected owner and primary-clock bounds in the same transaction.

Only the enrolled phone's distinct installed acknowledgement completes the
restoration. A saved approval or received status alone supplies no physical or
content permission. Exact installed retry returns the original time, including
through verified retained manifest ancestry; it never extends a lease or
translates an old message into a new connection. Current content consent and
per-message permission remain separate.

Interrupted owner requests retain exact opening/core/signature bytes. Passive
status never allocates or renews. Expired never-approved predecessors may close
only through an explicit fresh reservation and immutable linked closure history.
Signed observation history permanently withdraws original fallback on that full
connection. Unknown work remains retained. At most one refresh is accepted per
binding/full connection; another sample requires an explicit new connection and
approval, preserving old records.

The closed owner route family is
`/v1/account/sealed/payload-profile/selection-refresh`: `challenges`,
`challenges/status`, `challenges/proof`, `approvals` and `installed`, all POST.
The existing same-origin cookie and `x-zrotext-csrf` contract applies. New
mutations also require the genuine management budget. Canonical UUID/base64url,
closed duplicate/unknown-field refusal, finite JSON/time bounds and static JSON
errors apply. Device proof/installed frames use the actual authenticated03
socket; copied frame actors cannot select another session.

The optional router remains absent from main startup. Source composition and
synthetic ordinary-runtime tests do not establish actual browser custody,
Android hardware/SIM continuity, carrier delivery, production enablement or
release readiness.
