## Current product boundary

The server has conditional HTTP routes for account auth, device enrollment and a private synthetic message test. It can issue a writer-fenced synthetic execution grant and durably acknowledge device evidence only under explicit runtime/account/recipient allowlists, one-shot phone readiness for the exact recipient digest, and writer dispatch authority. The Android authenticated socket now has a manually armed, one-attempt synthetic grant and radio path with durable event replay and a pre-radio one-use journal boundary. It has passed local build/database tests and the Samsung app launch, and a separate token-gated M0 WSS heartbeat passed on the Samsung, but no authenticated M1 WSS or carrier SMS has run; no SMS has been sent or received. SMTP transport and a durable verification outbox are implemented, but no live verification email has been sent. A Compose migration runner applies numbered SQL under an advisory lock and checksum ledger; its production TLS and restore path is not yet implemented. Sealed content, independent security review, public deployment, payment integration, and geographic redundancy remain unimplemented.

## M1 owner inbound metadata history (in review)

An owner-session `GET /v1/inbound/messages/{message_id}/events` route returns at most 20 tenant-bound events per page with stable UUID cursor pagination, classification, device and attempt IDs, timestamps, part count and content kind. It rejects unauthenticated access, another tenant's message, a cursor outside the selected message, and invalid page limits. The response uses `Cache-Control: no-store` and excludes sender, recipient, body, ciphertext, signature, digest and webhook secrets. PostgreSQL-backed route tests, the full Rust workspace, formatting and strict Clippy passed. The route is mounted with the owner webhook management service and therefore requires that service's configuration. It is read-only software evidence; no carrier reply or external webhook was used.
