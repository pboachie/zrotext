# Retained profile03 effect records

Migration119 adds a separate storage capability for one-use submit commands,
late outcomes and signed pre-entry closure. The database checks structural
source and transaction coupling. The server must independently authenticate the
current socket, retain its signature-verified enrolled point, verify all original
signatures and enforce current permission before calling the factories. These
tables and functions do not mount a device route or authorize radio operations.

Each genuinely new grant retains the original enrolled point and established
key ID in the same transaction as its grant, job, attempt and fence. The exact
Fetch362 transcript and original device-session commitment are retained too.
An older grant without this actor record cannot acquire one retrospectively.
Its existing receipt remains history only.

The first submit invocation returns `inserted=true` alongside its flat retained
receipt. The server may construct a one-use response only after independent
current checks and successful commit. Exact retries return `inserted=false`
with the original bytes and time. They cannot renew a grant or issue another
platform-entry permit. A retained outcome or closure assertion blocks a new
first submit even when no submit receipt exists.

Outcomes retain exact original commands and deterministic state results. A
missing generic message is not recreated. Contradictory evidence while an
attempt is active keeps its busy fence UNKNOWN. If its fence was already
submitted or failed, that terminal fence remains terminal; a later message's
busy fence is not displaced.

A closure assertion alone can withdraw permission and mark an active attempt
UNKNOWN. It cannot release the busy resource. A fresh signed proof of the exact
permanent pre-entry record can finish that attempt as failed with no rearm.
The `ack_authorized` phase additionally requires its original accepted submit.
The reserved phase can cover an accepted command whose response was lost or a
command that never committed. No closure requeues a message, refunds usage,
deletes the original grant or allocates another attempt.

An outcome contradicting an accepted closure retains the evidence and creates
a permanent quarantine for the original account/device and original enrolled
point/key ID. New issue, fetch and submit refuse for that device UUID or that
exact original point within the account. Other devices and points are not
quarantined by this rule. Ordinary conflicts do not create this quarantine.

Proof challenges expire within the actual actor and native-backend lease.
An explicit replacement may close only the exact expired, unaccepted
predecessor. Original cores and closure links remain immutable. Sixteen new
replacements per fixed day are shared across connections for the original
account/device; initial challenges and exact retries do not reset that counter.
Request admission remains a separate server obligation.

The seven ledgers survive message, line, session and device erasure. Account
erasure may cascade their complete history. Runtime access is SELECT plus six
narrow controls; direct writes, truncation and internal helpers are denied.
Every new security mutation versions the actual account anchor at unchanged
selection epoch. Exact historical retries do not touch it. The closed schema
validator pins function bodies, all output types and modes, constraints,
triggers, ownership and privileges. It is a structural prerequisite and grants
no authentication or current content permission.

A new outcome command uses the time of its first durable authenticated
assertion. The phone must retain the original raw callback fact and wall time
separately, obtain a genuine correlated history-clock sample, and persist the
command before upload. Completed or possibly sent commands keep their original
time and bytes. A no-submit closure must permanently exclude platform entry
before waiting for that clock. The database checks diagnostic bounds against
actual primary time; it cannot attest these phone-side facts or provide the
clock producer, local barrier, or hardware proof implementation.
