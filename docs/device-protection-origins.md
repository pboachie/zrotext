# Device protection origins

The first-origin storage capability retains one protection setup command for an
enrolled device and signing point. It is available before root enrollment, line
setup or payload-profile election. It creates no keys, local protection pin,
capture counter, content permission or SMS authority. The socket adapter must
retain the exact signature-verified enrolled point through its session claim;
reading the current device row is not a substitute.

An opening copies the still-retained approved pairing source before any Android
provider call. It retains the actual creator, point, fingerprint and source times,
without pairing secrets or invented approver/session evidence. A pruned source or
unproven older key history is unsupported. The installation must also retain its
original local command and individual irreversible canary, HMAC and two AES
provider entries. Neither empty tables nor matching aliases prove eligibility.

The immutable association commits the original public HMAC probe and ordered
journal/withdrawal AES probes. A proof attempt has a server nonce and at most a
30-second window bounded by the actual device and hosted-backend leases. The
server must independently verify the enrolled-device and distinct-canary
signatures before acceptance. SQL structure and hashes are not signature proofs.
Only an accepted receipt retains the complete signed packet.

An explicit proof recovery closes its exact unaccepted predecessor permanently
and creates a new nonce over the same provider results. It never repeats provider
generation. Sixteen new recoveries are allowed per fixed 24-hour window for the
original account/device across connections; the initial attempt is excluded.
Exact retries preserve all original times, bytes and budget history. Separate
authenticated request admission still applies to every retry and status request.

Enrollment identity changes, revocation and deletion derive permanent retirement.
Restoring the old point does not revive the origin. Every public control and
status operation refuses a retired origin; original backend history remains until
account erasure. Ordinary suppression-health withdrawal is a separate condition.
Reconciliation of a nonretired accepted receipt may support explicit late local
installation only after checking both original signatures, every original local
provider result and existing-key probes. Status alone never installs protection.

The runtime can read the five ledgers and execute the four narrow controls. It
cannot modify those tables directly. Each new mutation versions the actual
account anchor at its unchanged selection epoch; historical retries do not. The
closed capability checks exact schema, declarations, bodies, ownership and ACLs.
Actual per-transaction native hosted entry remains mandatory. This storage slice
does not by itself mount the authenticated socket or Android setup adapter.
