# Jules reviews

Jules reviews an owner-authored PR when it is opened ready for review or leaves draft. A trusted scheduled run starts reviews for other ready owner or Dependabot PRs, up to two missing reviews per run. Dependabot-triggered workflow runs are skipped because they cannot use the configured Actions secret. A submitted comment or change-request review from a repository owner, member or collaborator starts an advisory `/jules address` session. The owner can also comment `/jules review` on an eligible same-repository PR to request a fresh review, or `/jules address` to request a focused comment-fix session. The Actions workflow polls for the result and posts an advisory PR review from `github-actions[bot]` with a link to the Jules session. It never approves or merges a PR, and Jules does not publish comment fixes automatically.

A `/jules address` session receives only two kinds of feedback: Jules' latest review of the PR, as published by this workflow from `github-actions[bot]`, and comments, inline comments and reviews whose GitHub author association is owner, member or collaborator. Comments from other accounts, including other bots, are left out, and text that claims to come from Jules or a maintainer does not change that; only the author identity recorded by GitHub counts. The workflow skips comment and review events from other accounts before the job receives the API key.

The integration runs from the trusted `main` workflow. It does not check out PR code in Actions. The API key is stored in the repository's `JULES_API_KEY` Actions secret and is sent only to Jules over HTTPS. Workflow dispatch with a PR number and mode is also available to repository maintainers.

Reviews are limited to branches in this repository. For a stacked PR, Jules reviews the change against that PR's base commit rather than all parent changes. A review is marked stale if the PR head or its base commit changes while Jules is working. The schedule avoids repeated sessions for the same head when its base changes; request a new review after updating the parent branch. Treat Jules findings as a second opinion alongside CI and maintainer review.
