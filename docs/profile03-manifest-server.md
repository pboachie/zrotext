# Explicit profile03 manifest server composition

The optional library manifest router installs public same-root03 successors and
serves their original history. Startup does not mount it automatically. It is a
source prerequisite for full messaging, not a declaration of runtime readiness.

A new install authenticates the ordinary browser cookie, configured Origin and
CSRF proof, commits separate request admission, then verifies a genuine current
password and one-use factor in the caller's held transaction. It independently
verifies the original registration, activation and election signatures, exact
root-signed successor policy and browser-key possession before calling the
narrow database factory. Original receipts and current owner/root/deadlines are
rechecked after waits. Any refusal rolls back the new factor and mutation.

An exact historical retry returns the retained receipt before another factor is
consumed. A freshly authenticated session of the same original user may observe
the original public evidence. This does not grant permission to reuse the old
session, re-sign, renew time or translate old content. An unknown response keeps
the original opening and exact bytes; it never opens a replacement implicitly.

History pages contain at most eight entries and 64 KiB of raw public entry
material, bound to an exact selected tip and prefix commitment. Every original
signature remains available. A private bounded cache retains independently
verified cryptographic prefix progress, with at most eight pages and two
seconds of work per call. Incomplete verification refuses current effects and
can resume on the next call. Cache entries are reselected against actual
immutable rows, exact original evidence, current root/binding and the closed
schema/runtime checks. Before cache reuse, a narrow read recomputes the complete
retained prefix against the exact selected tip; changing an intermediate
received signature refuses even if the tip and stored prefix remain unchanged.
This structural retention check supplies no cryptographic authority. Cached
signatures were independently verified, and every new suffix is verified before
publication. Entries contain no owner, factor, lease or effect permission.
Newly inserted uncommitted manifest progress is never published to the cache.

The original first-only current endpoint retains its fieldset and refuses a
later selected tip. The additive manifest-current projection separates current
signed material from the ten unchanged original evidence fields. Physical
availability requires the actual full device lease and independently verified
original or installed refresh evidence. An installed refresh remains tied to
its historical signed manifest and must preserve physical key identities
through verified accepted ancestry to the actual current tip. Ever-signed
refresh history permanently fences original fallback for that full connection.

Device history and exact-tip readback are authenticated bounded reads. Readback
confirms the held selected tip on the actual connection; it attests neither
hardware custody nor content consent. A phone independently verifies the full
chain and prepares its durable highwater before matching readback and reader
availability publication. The server never fabricates that local state.

Cold recovery first reads `/manifests/original` under genuine ordinary owner
authentication, or `payload_profile_manifest_original03_request` on the actual
authenticated full device connection. These closed replies contain only the
unchanged original ten-field evidence and its actual retained line/binding UUID
association. The browser or phone independently verifies the original proofs
and derives the base prefix before requesting ancestry. Neither reply selects a
current manifest or asserts physical/content permission. An owner may read this
public history while the phone is offline; the device path requires its actual
current full lease. Existing first-only current consumers stay unchanged.

All existing intervals, messages, attempts and liabilities retain their original
context. Renewing a manifest or replacing browser custody supplies no new
content interval, quota, grant, signed fetch or one-use radio authority. Those
remain separately typed and independently qualified integration requirements.

The public transport schema describes closed candidate fieldsets. Canonical
binary encoding, signed-storage integer bounds, exact source selection,
signature verification and currentness are additional runtime checks. Source
and schema tests do not establish browser storage, phone or carrier behavior.
