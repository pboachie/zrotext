# Held profile03 content selection

Content consent and reviewed sends use a separate held selection borrowing the
actual caller transaction. It authenticates the actual original owner proof,
reads the complete accepted manifest ancestry and retains an opaque verified
selection. The original first-only current endpoint keeps its strict contract.

Current signed material and prefix are separate from the unchanged original
registration, activation and election evidence. Every cache reuse checks full
retained original linkage; the cache stores no owner, device lease or effect
permission. A later manifest is selected only through the complete producer,
never a caller boolean, version arithmetic or parsed JSON projection.

The physical proof is a typed original activation or an independently verified
installed refresh receipt. Its content commitment is derived inside that held
producer from the actual binding, election, device lease and original received
proofs. A refresh is verified at its own historical manifest, then physical key
identities remain continuous through the actual accepted ancestry. A signed
refresh permanently withdraws original fallback on that full connection.

Before later composition the actual owner records, lease, selected manifest and
physical proof are revalidated in the same transaction. Sign-out and revocation
refuse even while public cryptographic progress remains cached. Selected
message and consent signer roles still require their independent root-selected
role, scope, lifetime and custody checks. No old interval or admitted message is
translated into renewed permission.

The optional interval library router provides reservation, authenticated request,
passive status and owner Stop. Its device hooks provide the exact phone approval,
installed acknowledgement, status and device Stop. It uses the closed interval
storage and separately verifies each original signature. Reservation alone never
discloses a request to the phone or activates content permission. Only the exact
installed acknowledgement completes activation; a received phase is not proof.

The router is absent from main startup. Actual PostgreSQL ceremony qualification
and browser/device acceptance remain separate requirements. This slice does not
queue messages, issue dispatch grants, fetch ciphertext or execute radio work.
It grants no live sending, deployment, carrier or release readiness.
