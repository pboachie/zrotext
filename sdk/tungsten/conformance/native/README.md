# Generated Rust and Go wire acceptance

This lane builds small generated-dispatch consumers against the exact reviewed
foundation and Tungsten source listed in `dependency.json`. The runner checks
the inventory digest and generated bytes, copies sources to a temporary directory
and overrides unavailable registry runtimes with that verified source.

```sh
python3 sdk/tungsten/conformance/native/run.py --foundation /path/to/foundation --source /path/to/lf-tungsten
```

First generate the foundation using its `scripts/tungsten_sdk.py --source
/path/to/lf-tungsten --check`. Rust 1.88, Go 1.26.10 and Python 3.12 are the CI
compiler/runtime baseline. The generated Go source-language floor remains 1.22;
this lane does not qualify the unsupported Go 1.22 compiler. Dedicated CI prepares
these source checkouts.

The shared synthetic HTTP suite covers bearer scope, preflight validation,
cursor page requests, strict malformed-success rejection, zero retry on reads,
uncertain sends with caller-owned keys, and cross-origin/mutation redirects.
This exercises generated typed dispatch with real native HTTP on loopback;
it is not a deployed acceptance or registry-installation claim. Cursor request
coverage does not qualify automatic multi-page iteration.

Same-origin read redirect refusal remains blocked by
[Tungsten #65](https://github.com/pboachie/tungsten/issues/65). Both native
runtimes follow those redirects in their send loop, independently of retry
counts, without a public disabling option. `probe_redirect.py` reports observed
request paths and outcomes after the passing suite; it deliberately never
reports redirect safety as qualified. Cross-origin and mutation redirect tests
do not imply blanket redirect refusal. No production policy is relaxed here.
