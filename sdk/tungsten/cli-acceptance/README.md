# Generated Rust CLI acceptance

This separate lane depends on the exact foundation commit in `dependency.json`.
CI checks out that commit and generates its reviewed outputs using its pinned
Tungsten source. The runner verifies the inventory digest and generated bytes,
then builds a temporary Rust CLI with explicit runtime source overrides.

Run with Rust 1.88 and Python 3.12 or newer on the same platform:

```sh
python3 sdk/tungsten/cli-acceptance/run.py --foundation /path/to/foundation --source /path/to/lf-tungsten
```

The foundation must already have generated outputs. Its `scripts/tungsten_sdk.py
--source /path/to/lf-tungsten --check` command prepares them. The checkout must
use canonical LF templates. The verified runner supplies the freshly built binary directly to the test
module. Environment variables cannot select an executable.

All requests stay on a synthetic loopback HTTP server. Tests exercise previews,
partial confirmation, missing credentials and idempotency, redacted diagnostics,
one-attempt ambiguous sends, and read-only reconciliation without resubmission.
A status of unknown remains unknown; reading status is not proof of delivery.
No tests contact a deployment, send SMS, publish packages or establish sealed
reader, key custody or release readiness. Source dependencies are deliberate;
this does not demonstrate registry installation.
