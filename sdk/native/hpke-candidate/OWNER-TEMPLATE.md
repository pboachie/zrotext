# Candidate current owner templates

Go `OwnerTemplateReader` and Rust `owner_template::OwnerTemplateReader` load the latest opaque encrypted template from one configured HTTPS owner origin. They expose cold-read behavior only. A returned snapshot explicitly does not acknowledge a saved request, match a pending write, authenticate plaintext, or grant approval/send permission. Use the separate authenticated template opener for plaintext.

The trusted application supplies independently authenticated conversation binding and callbacks for current owner authority and the owner session. Binding captures account, device, line, interval, session, generation, peer, phone-reader identity and archive-reader identity. Session input contains the exact configured origin, an owner cookie and CSRF value. No browser cookie extraction or login is performed. Workflow bearer/output tokens are not accepted. Cookies from responses are never retained.

Each read checks current owner-session/consent/active state, root-pinned verified profile02 manifest, exact binding, role2 workflow permission and matching active role4 workflow signer. It tracks nondecreasing current comparison, manifest version, exact same-version digest, enrolled/current root and generation. After loading bounded bytes, it verifies exact expected template/binding/peer digest scope and a valid P-256 encapsulated point, then rechecks current authority before publishing the snapshot. The observed template revision cannot decrease or change bytes at the same revision. Newer ciphertext remains opaque until explicit AEAD opening.

The application chooses whether to enable the client; disabled clients perform no HTTP. A configured deadline is 1..10000 milliseconds and is shortened by current authority freshness and key/manifest/template expiry. HTTPS uses platform trust plus optional independently trusted CA roots, no environment proxy, no redirects, no response cookie jar and no automatic retry. The deadline includes the full response body. Authentication failures close the instance. Explicit `close`/`Close` suppresses late results; Go also accepts caller cancellation.

Trusted callbacks must not reenter the reader and should honor the supplied context/deadline. The foreground refuses on cancellation/deadline even if a callback stalls. At most eight workers per runtime process are admitted, and a stalled worker retains its slot and the reader's busy state until it actually settles. This bounds retained work; it does not terminate arbitrary application callback code. Rust polls shortened callback deadlines at intervals no greater than five milliseconds. State is in memory and does not establish restart persistence or server freshness independently of the callbacks.

## Opaque save messages

`TemplateSaveRequest` captures a nonzero canonical request UUID, expected revision 0..127, exact next scope revision, bounded matching ZTWT01 envelope, owned ciphertext, transport digest and headers for the owner template route. It performs no HTTP or key/authority verification and is not a review ticket. Its receipt method requires the exact canonical `{"revision":N}` response used by the maintained owner client, rejecting whitespace, numeric alternate spellings, BOM, duplicates and extra fields. This is deliberately stricter than the standalone maintained `templateSaveReceipt` JSON helper; it matches the owner client's subsequent canonical-byte check.

Prepare/review tickets, commit, explicit retry, reconciliation and durable pending intent are not supplied by this cold-reader surface. Equal retrieved ciphertext cannot acknowledge a prior save. Those effects require a separate owner-client state machine and current authority review.

## Qualification

`test-owner-template.py --producer PATH --binary PROBE` (or trusted shell-free `--command-file`) requires clean maintained revision `26e876da9f34372d9cf26511993cf633971e0037` with its TypeScript SDK built. It uses fresh synthetic TLS keys and a signed maintained fixture, checking real HTTP headers/call counts, body bounds/deadlines, owner/session/current changes, callback settlement, opaque head consistency and maintained cold-reader differential outcomes. The default post-dispatch callback budget is 100 milliseconds. Test consumers with slower TLS initialization may declare --deadline-case-ms (100..2000) explicitly; held-body and late-callback controls scale with that caller budget while the 100-millisecond pre-dispatch refusal remains unchanged. The runner prints the chosen profile and verifies the late callback actually executes. No live owner server, browser, provider or device authority is exercised. Package consumers are qualified separately.

Rust requires 1.97.1 and Go requires 1.26.9, unchanged from the native candidate package. No dependency was added; Rust reuses the reviewed reqwest policy and Go the native explicit direct HTTP transport. Immutable session strings/runtime/provider copies do not carry a secure-erasure guarantee.
