# Native owner workflow context persistence

Experimental Rust and Go companions implement the maintained owner context ciphertext persistence lifecycle for kinds 1, 2 and 3. This is neither a context decryptor nor a capability to execute its contents. Context cryptography is documented separately.

Go exports `NewOwnerWorkflowContextClient(OwnerContextOptions)`; Rust exports `owner_template::context::OwnerWorkflowContextClient::new(ContextOptions, ContextReviewer)`. Options select one immutable owner binding, context identity and kind, an HTTPS origin, independent current authority and owner-session callbacks, and a review callback. Rust callbacks share the existing owner call cancellation/deadline API. Go callbacks receive a context. Returned current manifests must be genuine verified native tokens; callbacks do not manufacture authority from JSON.

`Prepare` (Go) or `prepare` (Rust) captures caller-selected request identity, expected revision, exact scope and ciphertext, and consumes review without making an HTTP request. `Commit`/`commit` submits that exact record once. A successful canonical POST revision receipt is followed by an exact ciphertext GET and fresh authority checks before returning an acknowledged receipt. Only the live foreground caller can acknowledge and clear pending state.

A failed or ambiguous dispatched write retains its pending identity. `RetryUnknown`/`retry_unknown` explicitly replays the exact saved request and bytes; no retry happens automatically. `VerifyUnknown`/`verify_unknown` reads the current head. An equal head returns an unacknowledged receipt and preserves uncertainty. A compatible newer head is `not_current` only following an acknowledged POST; reconciliation alone cannot acknowledge the prior request. Known first-attempt rejection is distinct from that same rejection after an uncertain attempt. Both POST and reconciliation are limited to three attempts.

`Close`/`close` invalidates tickets and clears retained ciphertext once an in-flight worker settles, but preserves the pending public identity. After uncertain dispatch, later calls remain `unknown` with `closed` or `expired` classification. The deadline never renews: it is capped by caller timeout, current freshness, context expiry, manifest expiry and selected reader/phone lifetimes. Blocked caller callbacks retain bounded admission until actual settlement; they cannot publish a late acknowledgement. A concurrent losing preparation cannot erase a reviewed or uncertain record.

Transport uses TLS verification, owner cookies and CSRF, no proxies, redirects or implicit retries. Full response bodies and callbacks share the total deadline. The library owns no server session or key deletion. Tickets are instance-bound and are not a restart journal; applications must retain their own durable request identity for recovery beyond the instance. No service activation, live owner session, installed archive acceptance or production readiness is inferred from source tests.

The synthetic HTTPS runner `test-owner-context.py` takes `--producer` pointing at clean public revision `8982ee9e96be15801a424708afa603ef708a8a5b` with its TypeScript SDK built, and either `--binary` or a trusted JSON argv `--command-file`. It compares exact requests, errors and acknowledgement outcomes against that revision's maintained client. Positive transport cases allow four seconds; short pre-dispatch controls remain 100 ms, and explicit post-dispatch deadline cases use `--deadline-case-ms` (200 ms by default). No live credentials or production endpoints are used.
