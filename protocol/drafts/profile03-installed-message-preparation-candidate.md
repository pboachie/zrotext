context and all three original consent receipt signatures to unsigned outbound
ciphertext and a private explicit V2 review context. It refuses missing phases,
changed signatures, foreign context, unsupported routing or message bounds.

the message cannot outlive the original interval, owner or current key/permission
deadlines. Exact peer, original owner/session, manifest/election and selected
recipient/signing identities come from the same private context.

The trusted application must obtain that context through the fresh authenticated
owner history/context read and supply the actual original server receipt times.
Component signature checks do not establish their transport/storage provenance,
durable phone installation acknowledgement, physical permission or key custody.
A public active flag, downloaded phase or copied context projection cannot
substitute for these inputs. The existing low-level original codecs are unchanged.

All input descriptors, statement/signature/routing bytes are captured before
asynchronous work. A supplied real AbortSignal and checked monotonic clock guard
verification, private context derivation, encryption and synchronous final release.
Stop, expired interval/permission or regressed time prevents preparation release.

The returned preparation and review handles are private component identities,
not a one-use signing or execution permission. The browser still must retain its
original review, exact unsigned ciphertext and first signing burn before invoking
the retained role05 signer, then exact completed envelope/V2 intent and second
burn before the second signature, then the completed public packet before HTTP.
Every ambiguous signature or upload retains its original identity and history;
there is no automatic recomposition, replacement ID or effect retry. Plaintext
and content keys remain outside durable recovery. Returned statement bytes are
an owned display projection and cannot change the private preparation/review.

This prerequisite is not the mounted browser composer/journal, hosted V2
admission, typed phone execution or carrier acceptance. Tests use real SDK
root/election/manifest/three-receipt signatures, ciphertext/HPKE opening and V2
signatures; none of those fixtures supplies actual held server or hardware state.
